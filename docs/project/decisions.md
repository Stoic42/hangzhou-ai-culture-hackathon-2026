# 讨论与状态记录

更新至2026-11-07。本文件只记录当前作品《当代妖怪收容所》的有效结论；初期《拓》《蓝》《剪》记录已归档。

## 2026-11-07玩法改版结论

针对“干等倒计时判负、过程枯燥、输入只有三种手势”的试玩反馈，本次拍板如下，细节与理由见[ADR 002](../../.codestable/requirements/adrs/002-pressure-value-replaces-countdown.md)：

- 压力值（侵蚀式自动上涨）取代60—90秒硬倒计时，输赢由操作决定，不操作约20—30秒判负。
- 输入动词新增方向滑动、连点/节奏、摇一摇（IMU只做SHAKE）；语音仍不进游戏规则。
- 服务器生成器从单一模板扩为4个验证模板：拒绝×3、方向滑动对抗、连点节奏、摇晃甩掉。
- 结局屏增加S/A/B/C评级与妖怪吐槽/夸奖文案，不做每局参数随机化。
- 板载用户KEY键：单击返回上一级（游戏中单击直接退出并记“被带跑”），按住为PTT语音输入；PWR键不复用。

## 2026-11-06本次接入检查

用户确认当前微雪板屏幕有画面、能够出声；本机确认CH342的COM6/A与COM9/B均可打开。同步远端后核对到既有离线T5原型及微雪1.75寸AMOLED配置，保留既有架构和已报告的实现进展，详见[硬件检查记录](hardware-check-2026-11-06.md)。本轮没有刷机或修改实现。

用户对外概念包含对熬夜、久坐、吸烟作情感化抗议；当前代码实现的是预设规则和触摸游玩，尚无自动感知上述行为或外接舵机控制。概念愿景与已实现范围分别记录，不据此改动已拍板的独立T5游戏架构。

## 当前方向

- 当前任务是开发《当代妖怪收容所》，内部roadmap标识继续使用`bad-habit-buddy`。
- 每只搭子是由用户的当代坏习惯生成性格与游戏规则的妖怪，不让机器代替用户完成传统工艺品。
- 使用三台涂鸦T5-E1-Touch-AMOLED-1.75-G作为彼此独立的搭子个体。

## 已明确的体验与架构

- 网站不是必需入口；设备自身可完成按住说话、确认候选搭子、生成、下载与游玩。
- 板载麦克风用于采集语音，识别、语义理解与生成由服务器完成。
- 预设搭子与已下载搭子均可离线切换和完整游玩；只有首次生成或首次获取设备尚未拥有的搭子需要联网。
- 所有已发布搭子进入无需登录的全局公共搭子库，不使用分享码、设备配对或实时联机。
- 创建分为两阶段：服务器先提供名称、性格和玩法简介；用户确认后，这些内容保持不变，由服务器展开成具体逻辑。
- 自定义搭子由服务器组合经过验证的行为规则并下发规则包，不下发AI现场编写的任意代码；预设与自定义搭子共用规则格式和执行器。
- 已发布搭子不可覆盖修改；修改形成新的搭子。
- 每只搭子提供一局短时完整游戏（压力值机制下单局自然收敛于约20—60秒），具有“破解成功”或“被搭子带跑”两种结局与S/A/B/C评级，不做长期成长与连续关卡。
- 搭子只保留当前一局内的操作记忆，重新开始后恢复初始状态。
- 公共库搭子必须能在标准T5-E1设备上独立完整游玩，不依赖必需外设。
- 三台设备分别独立运行；服务器仅承担生成与公共库存取。
- 搭子采用参数化形象，不要求为每只搭子生成并下载独立AI图片。
- 麦克风用于联网创建搭子（KEY键按住说话）；正式游戏使用触摸与摇一摇操作，不生成依赖语音识别才能离线游玩的规则。
- 原始录音不进入公共库且不长期保存；公共库只展示创作者确认的名称、性格与玩法简介，不公开创造者原话或具体执行逻辑。

## 尚待验证
